# 本地服务与 AI 桥接

## 启动

需要 Linux/macOS 等 POSIX 系统、Python 3.10+、浏览器，以及已安装并登录的 Codex CLI。路径保护、进程组终止和实例互斥使用 POSIX API；当前实现未支持原生 Windows。当前 CLI 参数须通过 `codex exec --help` 核对；本桥接使用 read-only、ephemeral、output-schema 和 output-last-message。官方说明：[Codex developer commands](https://learn.chatgpt.com/docs/developer-commands#codex-exec)。参数适用性仍以所装 CLI 为准。

服务监听 `127.0.0.1` 的随机空闲端口，仅服务 skill 的静态资源和受约束的 API。输出目录需可写；不需要把仓库变为可写。`--port` 可指定本地端口，`--model` 可选择用户指定模型，`--timeout` 可设置请求期限。桥接使用 `--ignore-user-config` 避免加载用户的全局 MCP/工具配置，仍使用既有登录；默认使用 CLI 内置模型选择，可通过 `--model` 明确指定。不会嵌入 API 密钥或禁用现有 execpolicy。

`--open` 用系统默认浏览器尝试打开 URL。无桌面、远程机器或执行环境阻止本地 socket 时，会报告失败。使用已有端口转发设施在自己的浏览器打开；默认不监听公网，不上传托管。

Host/Origin 校验要求使用打印的 `http://127.0.0.1:<port>/`；SSH 转发时保持相同本地端口。改用 `localhost`、不同端口或代理域名会被拒绝，除非另外实施并验证相应的 origin 配置。

页面必须通过打印的 http URL 打开；直接双击 HTML 只能看到静态壳，无法聊天。停止服务使用运行终端的 Ctrl+C；长期运行用环境已有的持久进程方式，避免会被工具回收的短命进程。

## 两种模式

服务在独立 Codex 任务中发送当前图、选择、问题和近期对话，并要求任务只读检查目标仓库。通过结构化 JSON 接收 answer、replacement_view、new_views。问答响应包含修改时直接拒绝；修改响应受服务端范围校验：选中元素模式只改选中元素，明确授权的邻居只允许几何调整；拆分节点或新增关系需整个视图模式。默认自动应用，可勾选先预览；应用时再次检查图谱版本和来源指纹。完全无变化的响应会被拒绝，来源或详细说明修正可单独应用。修改不会编辑仓库源码。每个请求可以消耗现有 Codex 账户额度，耗时取决于模型与读取规模。

CLI 的 read-only 是写入隔离；「只读取目标仓库、不使用外部服务」是任务指令，不能当作操作系统级读取封锁。本服务的浏览器源码接口另外执行引用范围与路径检查。如果目标环境需要严格封锁仓库外读取或所有外部工具，须在既有容器/沙箱中提供相应隔离，再启动服务。

受约束的结构化输出、来源存在性和链接检查不能证明所有架构解释正确。新增 verified 关系仍需要模型回到代码核对；用户可以点击证据审阅。仓库内容只是待分析资料，不能授权工具扩大权限。

`atlas.json` 是初始种子；第一次成功提交后，同目录的 `atlas.json.bridge-state.json` 是当前图、对话和历史的权威状态，用单文件原子保存避免它们版本不一致。重新启动会恢复此状态。导出按钮下载当前图，后续审阅请校验导出文件，而非旧种子。不要把旧 sidecar 搬到另一个仓库复用。

同一实例通过相邻 `.lock` 文件互斥，第二个服务会拒绝启动；停止或退出后释放锁。对话最多保留最近 60 条，撤销保留最近 20 版，界面恢复使用当前权威状态。已经发给 CLI 的请求在服务退出时终止，未提交的模型响应不会覆盖保存结果。

实例目录可能包含目标仓库的分析资料，它们不进入 skill 目录。请求快照和临时模型输出在任务完成后清理；未成功的回答不改变图。静态导出不包含会话 token。

## 常见问题

- **找不到 CLI / 未登录**：运行 `codex --version`、`codex login status`；用户在自己的终端完成既有登录流程。页面显示失败详情，不伪造答案。
- **CLI 不认识参数**：检查 `codex exec --help` 和已安装版本；更新兼容性或按用户选择的环境调整 bridge，不使用权限绕过参数。
- **模型失败或超时**：原图保留，可重试；用更聚焦的选择与问题缩小任务。检查终端诊断，但不要输出凭据。
- **409 版本过期 / 正在处理**：重新加载状态，等待当前请求完成后再次提交；不同标签页也共享同一实例版本。
- **证据失效**：使用「检查来源」对已引用文件重新计算 SHA-256。`unknown` 表示尚无核对基线；`stale` 表示变化；`unavailable` 表示缺失或不可安全读取。选择受影响视图刷新，不自动更新全仓库。hash 相同只能说明所监测文件内容相同，不能证明事实正确或所有依赖已覆盖。文件删除不会阻止打开旧图或撤销。
- **图过密**：围绕具体问题分解视图，用明确路由和跨图定位；不要只扩大画布。

运行开发回归：`python3 <skill-dir>/scripts/test_bridge.py`。这些测试使用临时合成仓库与受控 provider，不替代真实 AI 连通测试。测试输出不应分发成实际项目图。

## 升级与回退

v0.2.0 保留原 atlas JSON 格式；sidecar 升级为 version 2，按视图保存引用文件的 hash。旧图没有基线时显示未知，首次监测不等于模型已核对。刷新某视图后只更新该视图的基线，其他视图继续保留各自的核对状态。

加载 v1 sidecar 后，首次写入新版状态前会逐字节保存独立 v1 备份 `<sidecar>.v1.backup.json`。若回退后旧版又写入了新状态，再次升级会保留原备份，并另存 `<sidecar>.v1.<SHA-256>.backup.json`。回退时选择对应状态的备份。回退先停止服务，将当前 v2 sidecar另存，再用对应 v1 备份恢复原 sidecar 文件名，然后运行 v0.1.0。新版制作且没有 v1 备份的实例，可把当前图导出为新的种子并在新的输出目录运行旧版本；这不会带回聊天或撤销历史。发行 ZIP 只含通用程序，不含任何实例状态。

预览暂存在服务内存。取消不写图；重启丢弃未应用预览。应用前若 revision 或引用文件变了，会拒绝并要求重新生成，不接受浏览器自行提供的候选图。来源监测仅覆盖图谱已引用的文件；未登记的依赖变化仍须人工判断和重新调查。

## v0.3.0 节点语义

新生成图的每个方块必须对应数据结构或功能块，节点 kind 分别为 `data-structure`、`functional-block`，关系 kind 保持开放。旧实例可以继续打开与撤销，未分类节点会显示兼容提示，不根据名称自动猜测。新增和修改的节点必须分类；来源刷新要求所选视图全部节点符合新理念。可先选择整个视图，让 AI 将叙事步骤重构成实际对象与功能，再做局部修改。独立校验脚本默认严格检查两类节点。
