# 改进验收与边界

本次改进借鉴图编辑器的差异预览、局部操作和版面检查，以及仓库解释工具的证据回溯。它不宣称比商业产品全面，也不引入托管、账号系统或团队协作。保持 Python 标准库与纯浏览器运行，用可复现行为评估结果。

## 固定路由对照

运行 `node scripts/test_routing.js`。Node 只用于开发检查，不是 skill 运行依赖。

三张固定合成图包含横向障碍、纵向障碍和并行关系/自环，共五条默认路线；另检查有效手工路线是否保留。旧算法按 v0.1.0 的默认两折线路由计算，新算法调用实际浏览器路由模块。统计线段进入无关节点内部的次数，不把仅触碰边界算作穿越。

| 固定样例指标 | v0.1.0 | v0.2.0 |
| --- | --- | --- |
| 穿越无关节点的关系数 | 2 | 0 |
| 并行关系 | 可能重合 | 使用不同端口偏移 |
| 有效手工 points | 保留 | 保留；无效线路重新寻路并提示 |

脚本同时报告寻路耗时；耗时随机器变化，不能作为普遍性能承诺。小固定图无穿越不代表所有仓库自动排版成功。坐标仍由图谱作者设计，算法不移动未授权节点；拥挤、重叠、搜索上限或无可用路线需调整布局或拆图。

## 事务与证据检查

运行 `python3 scripts/test_bridge.py` 和 `python3 scripts/test_upgrade.py`。测试通过临时合成仓库及受控 provider 验证以下行为：

- QA 不改图；选中元素范围越权时整份候选被拒绝；授权邻居只能移动。
- 预览不写权威图、成功对话或撤销历史；应用时校验 revision 和来源；持久化失败保留旧状态。
- 引用文件变化或删除会提示；旧图仍可打开和撤销。单视图刷新不会把其他视图错误标为同步，多视图刷新失败不会提交一半。
- v1 实例迁移前保存原状态；发行包不包含实例图谱、来源片段或聊天。

文件 hash 检查与 JSON 校验不能证明解释正确。真实 AI 仍需检查代码与测试，浏览器仍需审阅文字、标签、箭头及事实。v0.2.0 README 的截图使用本公开 skill 的真实自分析及真实模型问答与修改；单次成功仍不能作为跨仓库模型准确率证据。v0.1.0 截图保持原有合成示例说明。

## 实际使用评估

选择公开或获授权的不同语言、不同规模仓库，记录被调查文件、版本、工作区变化、未覆盖部分。分别测试一次真实问答、局部修改、预览应用、源码变化后的刷新，并人工核对关键边证据。比较同一视图、相同视口下的节点穿越、标签遮挡、来源准确率、修改范围和响应耗时；保留失败样例。没有完成此类跨仓库评估前，不给出“适用于任何规模”或优于竞品的结论。

对目标仓库的测试结果和实例内容保存到该次输出目录，不上传到通用 skill 发布仓库。

## v0.3.0 节点语义验收

逐个方块指出它对应的类型、对象、函数或协作能力，再核对证据与边界。数据结构核对字段、身份、所有权和生命周期；功能块核对输入输出、入口和组成函数。仅把 kind 改成合规字符串不算完成语义核对。流程阶段、状态、问题和一般说明不能成为第三类方块。

新增回归检查独立校验器拒绝任意节点 kind、关系 kind 仍开放、旧图可打开和撤销、未变化旧节点可以保留，以及新增/修改/刷新节点必须归入两类。新版真实自分析截图展示 Atlas、View、Node、Edge、Proposal、SourceBaseline 结构，以及实际实现函数构成的功能块。
